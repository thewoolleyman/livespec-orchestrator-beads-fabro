# 002 — Genesis of the dispatch journal

[Back to index](https://github.com/thewoolleyman/livespec-orchestrator-beads-fabro/blob/master/plan/dispatch-control-plane/research/README.md)

**Archived — supporting research, 25 October 2026.** Retained as evidence for the current reports. Observations and source checks describe that date, not a fresh assessment of the running system.

The journal began as an **audit-output implementation choice**: Claude-coauthored commit `d49e76314` (2026-06-11) introduced both its append-only JSONL writer and the default `<repo>/tmp/fabro-dispatch-journal.jsonl` path. The upstream guidance it cited called for a machine-readable journal “for post-hoc audit” and was already explicitly non-normative (core v103). The journal acquired decision authority **reader by reader**: claim accounting in July, provider exhaustion and degraded-step persistence in August, fallback warnings in September, and proof attribution and recovery in October. Some authority was designed explicitly in the specification: agent-authored proposal `559659047` led to delegated **v074**, making journal history govern the next dispatch before that reader shipped. Other revisions, notably **v086** and **v116**, ratified existing checkout-local readers after implementation. **No historical maintainer-voice instruction selecting this pathname or approving this file as the sole durable carrier was found in the searched populations below.** Recorded delegations and an agent’s “Maintainer-approved” predicate amendment are narrower evidence. The strongest explicit storage rationale is the factory implementation’s comment in `83d26f3cd` (2026-08-28): “THE JOURNAL IS THE STATE, deliberately.” That is an agent implementation statement, not a maintainer quotation.

## Original artifact and writer lineage

The exact default is present in `d49e76314:.claude-plugin/scripts/livespec_impl_beads/commands/dispatcher.py`, lines 306–309:

    def _journal_path(*, args: argparse.Namespace, repo: Path) -> Path:
        if args.journal is not None:
            return Path(args.journal)
        return repo / "tmp" / "fabro-dispatch-journal.jsonl"

The same commit’s `_dispatcher_io.py` explains:

> `JournalFile` is the structured iteration journal the Dispatcher guidance requires (livespec non-functional-requirements.md §"Orchestrator-internal Dispatcher guidance"): append-only JSONL, one record per engine stage / loop event, machine-readable for post-hoc audit.

“Requires” is the implementation’s wording. The actual cited core guidance, verified at the local sibling core tree `6830d68a9f3b8256626c7e60b2150426d4c88aea` (core v107, committed 2026-06-11 01:05:28 UTC), `SPECIFICATION/non-functional-requirements.md:114–125`, says:

> This guidance is explicitly NON-normative on core's contract: core neither names nor verifies any of it …

and calls for:

> a **structured iteration journal**, machine-readable for post-hoc audit, recording each iteration's pick, dispatch, janitor result, commit (or rollback), and exit reason.

Core `fa48d2f2` (v067, 2026-05-18 UTC) had allowed “typically appended to a project-local file or written as commit trailers.” Core `01c8324b` (v103, 2026-06-09 UTC) made this non-normative guidance. These historical reads verify the original code’s named design source; they do not turn that source into a maintainer storage instruction.

The June writer created its parent directory and appended JSON/newline under a thread lock using `open("a")`. The introduced engine made decisions from command results and carried a write-only `JournalWriter.append` seam. Journal-history folds are later changes (`d49e76314`, 2026-06-11; individual introduction commits below).

The containing directory was already ignored by `69d8c616d` (2026-06-08), `.gitignore:2`. This is the repository’s `tmp/`, not the system `/tmp` or a `tempfile` automatically deleted at exit. Git nevertheless does not carry its bytes to another checkout/host. The pathname choice arrived in code, not a spec revision.

`a3a919066` (2026-07-11) extracted path helpers. `d4371adcc` (2026-08-26, `bd-ib-vwwlwp`) added attribution and moved two bypassing writers to the append chokepoint. `35cc3234e` (2026-10-19) extracted the writer into its current leaf to break an import cycle. None introduced the physical store.

A read-only streaming measurement at **2026-10-25 01:38:36 UTC** found **326,459,484 bytes, 503,995 lines**, first row `2026-06-22T21:43:08Z`, last row `2026-10-25T01:38:20Z`; size was unchanged before/after counting. This verifies the brief’s approximation. It does not date the design to June 22: `d49e76314` proves June 11 code.


## Class A readers named in the brief

This retains the brief’s grouping of readers whose decisions or reports change when history disappears. Their safety directions differ: warning disappearance is an observability loss, while proof-attribution failure can reject valid evidence. These are static source/history findings; no live journal was removed and no mutating Dispatcher path was executed.

### A1. `_dispatcher_step_persistence.py` — degraded-step admission gate

**First reader:** `83d26f3cd`, authored 2026-08-28 09:34:51 UTC, landed 09:55:36 UTC; subject `feat(dispatcher): close the preflight and post-merge step discipline`. That is the actual implementation design argument, not a maintainer quotation. It treats append-only outcome history as the durable carrier (`83d26f3cd`).

**State:** newest structured degraded `outcome` not retired by `step-clearing`, addressed by timestamp/item/step. **Spec:** proposal **`559659047`, 2026-08-25**, frontmatter `author: claude-fable-5`, identified the residual gap: a later homelab dispatch proceeded after an earlier degraded outcome. Delegated **v074 / `aac849d51`** already says:

> When the journal's outcome history for the repository names a missing REQUIRED integration point … the Dispatcher MUST refuse the NEXT dispatch …

Successful re-verification requires a clearing record; a committed waiver is the other escape. **Journal history as a gate input therefore preceded the implementation.** Choosing the existing local file as the durable carrier without another reconstruction source is the implementation’s refinement. ## Class B readers named in the brief — qualifications

The blanket label “fail CLOSED on an empty journal” is not accurate for all three. Absence/unreadability, a readable empty file, failed external measurement and missing proof are different cases.
